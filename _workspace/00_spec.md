# KeepCon 기능 명세 (검증 슬라이스)

전체 앱은 4개 페이지(로그인/설정·메인·스캔·공유)로 구성된다. 이번 하네스 검증은 경계면 버그가 가장 많이 나는 **스캔(생산) → 메인(소비)** 축에 집중한다.

## 스캔 및 추가 페이지 (생산자)
- 카메라 스캔 / 갤러리 불러오기 / 수동 입력으로 기프티콘 추가
- 세 경로 모두 최종적으로 하나의 Gifticon을 생성하여 GifticonRepository에 저장
- 신규 기프티콘의 소유자는 현재 로그인 사용자

## 메인 페이지 (소비자)
- 로그인 사용자의 기프티콘 보관 현황을 목록으로 표시
- 정렬: 만료임박순, 최신 등록순, 브랜드명순
- 필터: 상태별(사용가능/사용완료/만료), 카테고리별

## 계약이 반드시 커버해야 하는 크로스페이지 접점
- Gifticon 모델: 메인의 정렬(만료일·등록일·브랜드)과 필터(상태·카테고리)가 쓰는 필드를 포함
- GifticonStatus / SortOption / FilterOption enum
- GifticonRepository: 생성(scan) + 조회/스트림(main) 메서드
- AuthRepository.currentUser: 소유자 식별 (auth 페이지가 생산하지만, 이번 검증에선 계약 인터페이스 + mock으로 대체)
